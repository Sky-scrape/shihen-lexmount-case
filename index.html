时痕｜档案馆 + 追踪器

把 Lexmount 云端渲染作为 transport 接入「时痕」的历史月份回补：让被判为异常流量的检索矩阵重新跑得动，同时一条门禁都不放宽。

项目 时痕（档案馆 + 追踪器） 云端能力 Web Fetch /v1/dom/dump 实跑日期 2026-11-01
一句话结论：换出口解决了"取不到"，但后面还有两道闸——"走不完"和"该不该收"。云出口把被墙的检索矩阵从 0 格救回到正常产出、命中量追平付费 API；而候选从 122 涨到 220 之后，真正被修好的单媒体事件包只有 14 个（18%），11 个"第二家"是聚合平台转载。继续往下挖才发现：真正的问题不是关键词不够准，是候选的来源本身没有选题相关性——而这一点，是把前两道闸修好之后才看得清的。

00Lexmount 在项目里的四项功能（先看这个）

下面这些不是“用云平台做了一次演示”，而是这个项目里长期在跑的四项具体功能。四项共用一组凭证，但调用位置、触发条件、失败处理各不相同。

角色治什么失败触发条件一句话

边界一句话：云端取回的内容不构成存档证据（存档只认 Wayback / archive.today 的回放核验），也不参与事实判定。

01任务与卡点

时痕每个月把中文互联网的大事固定下来，并持续追踪"后来怎么样了"。为了让档案不只有最近几个月，需要回补 2026 年 1—3 月的历史月号。回补的第一步是检索矩阵：搜索引擎 × 关键词 × 媒体站点，逐格跑，每格拿一张结果页。

实测从本机与服务器直连 so / baidu / bing，首轮 30—40 个请求后就被判定为异常流量，返回 302 跳验证页。2—3 月的发现阶段一度出现「40 格里只有 0—1 格拿到结果」——抓不到结果页，这一格等于没跑，整月都补不动。换 IP 只能撑一轮。

02云端与本地各做了什么

角色承担的工作
Lexmount 云端 只做一件事：取字节。把搜索结果页渲染成完整 DOM 交回来（含验证码/反爬绕过），以及正文直连失败时的渲染回退。本次实跑 62 次调用，55 次成功。
本地管线 查询构造、DOM 解析、媒体注册表过滤、标题与日期校验、去重；正文抓取与质量判定；存档回放与 SHA-256 比对；三项审校与出刊排程。
人工 只做不可逆的判断：定政策（注册表、门禁阈值）、处置被拦下的草稿（保留 / 待补源 / 移除）、把结论写进报告。

关键设计：做成 transport，而不是新 engine

矩阵格子由「引擎 × 关键词 × 站点」决定，而引擎参与配置哈希。如果加一个「云端引擎」，给已完成的月份换出口就会被判「配置不一致」，只能 --force 全量重来。做成 transport（取字节的出口）后它不进哈希，可以对已完成的月份 --resume，只补被墙的那几格。这是这次接入里最重要的一行设计决定。

04三个比数字更重要的发现

反直觉 01

候选翻倍，不等于问题解决

交接候选从 122 涨到 220，看起来是大胜。但按"原包是否被修复"重算：原 79 个只有一家报道的事件包里，补源只救回 14 个（18%）。而这 14 个里有 11 个的"第二家"是今日头条——聚合分发平台，内容基本是转载。取一例实测：两篇正文的 6-gram 近重复率 1.000（门禁阈值 0.85），反转载门禁拦得完全正确。

所以真正独立的第二家只有 3 个包，占原来 79 个的 3.8%。总包数涨得比多媒体包快，因为新捞回来的多是"又一个只有一家报道的新事件"。

反直觉 02

三道闸：修好前两道，才看见第三道

把"第二家是真实媒体"的 3 个包单独送进月度管线复核，6 条候选全部被排除，理由分别是：常规行业销售预测与财经快讯、泛化防诈科普宣传、宏观财经数据例行统计、自媒体碎片化随拍、元旦例行新规盘点。

这些判定是对的，但当时我把结论下早了。把三个月的任务包按阶段拆开（npm run backfill:yield）才看清：这些候选主要来自档案通道——按注册媒体域名抓当月全部文章，天然没有选题相关性；同时"按注册媒体域名限定搜索结果"这个能力其实已经失效（四引擎两出口实测：so/baidu 回桩页、bing 不遵守 site:、博查设计上剥离 site:）。

所以加的不是"更准的关键词"，而是第三道闸：进事件包之前先过一遍选题判定。2026-02/03 实跑，两批候选 22 条全部落选（include 0）——这两个月是真的没有值得进馆的事件。这个结论不好看，但它比往档案里塞 20 条产业通稿更接近真相。

踩坑记录

状态记忆会让新出口永远不被使用

首次实跑时 124 次请求全部落在付费 API，云端出口一次没用。原因不是接入错了：补源阶段会继承上一轮"已知被墙"的引擎列表——上一轮直连确实被墙，但换了出口之后这道墙已经不成立。沿用旧状态，等于让新出口永远不被选中。

这类"修复看起来生效、实际跑的还是旧路径"的问题，比接入本身更值得记下来。

05未完成的部分

  • 1—3 月仍不能称"完成核验回补"。能过门禁的事件数只从 0 变成 1（2026-01-201 车厘子价格暴跌：剔除聚合平台后按单媒体口径合规，重新取证并通过 Wayback 回放验证）。
  • 部分包客观上只有一家报道。补两轮、换出口、用标题精确检索仍找不到第二家——这个结论本身值得信任，不该继续烧预算，改为"单媒体 + 人工三项审核"路径。
  • 部分正文取不到。例如 2026-01-202 的央视页面，云端 Web Fetch 取回 15KB 全是 cookie 挑战脚本，仍然判 no_content。无状态渲染对"必须先执行 JS 挑战、带上 cookie 才放行"的页面无能为力。
  • 反爬页已经做了第三级（云端真实浏览器），但结论要更正：真实浏览器打开那条央视链接拿到 186KB DOM（无状态渲染只有 35KB）、标题正确——取字节这一层通了；可是页面正文只有 57 字（一句导语加版权声明），它本身就是一个没有正文的视频页。所以"反爬取不到"只是表象，no_content 是对的结论。抓取能力再强也变不出不存在的正文，这类链接该走"视频页 → 不收录"。

06追加：把同一能力用到第二个失效上

上面解决的是"取不到"（检索被墙）。这个产品还有第二种失效——内容消失：新闻下架、帖子被删、原链接失效。这个失效一直没有观测手段，因为原有的链接检查器只做直连探测，会把三类情况判错：

为什么"链接打不开"不能直接用直连状态码回答
实际状态直连判定后果
出口级封锁（403 / 跳验证页）不可达把"我打不开"说成"内容消失了"
302 → 验证页重定向需人工复核无法收敛，人工没法逐条看
200 但是壳页 / 下架占位正常最危险：假装还在

新增的巡检把可达性拆成四态，判定链是「直连 → 云端渲染 → 组合结论」。硬规则：403、超时、验证页永远不会被判成"已失效"，只有 404/410 且两路一致才算；云端不可用时记"未能判定"，绝不降级。

云端只在直连没给出"活着"时才调用，这一次全量巡检只用了 2 次调用。其中一条值得单独说：Politico 的一篇报道直连返回 403、落地是验证页，云端渲染后 200、正文 1053 字——用旧口径它会被记成"不可达"，而读者其实完全读得到。另一条是视频页，直连 200 但正文只有 147 字，云端 160 字，两路都取不到正文，如实记"未能判定"而不是记成失效。

一个代码真的踩到的坑

首版把 challenge-platform 当"验证页"的强特征，结果 Politico 那个 1053 字的正常页面被判成门页。原因是 Cloudflare 会把这段脚本注入到所有受保护页面。改成"弱特征"——只在这一页几乎没有正文时才作数——并写进了单元测试。这类误判会让工具把最该被读到的报道说成"打不开"，方向正好相反。

0 条失效说明什么：已发布事件的来源链接目前都还在。这个结论本身有效，但它只是第一天的快照——四态的价值不在今天这个数字，而在于以后每次跑都能对比。

已经跑在线上：巡检作为一次性服务接进 compose，cron 每周一 10:00，报告留在服务器上供下一次对比。生产首跑与开发机的结果不同——服务器 live 64 / rendered-only 2 / dead 0 / unknown 1，比开发机多一条 rendered-only：同一条链接服务器直连失败、云端读到 3079 字。同一份内容，从两台机器看结论不一样，这正是四态要保留的信息。

07边界：放宽了什么，收紧了什么

云端出口本身只改"从哪里取字节"，以下判定一步都没动：

  • 结果页永远不是证据：候选仍要过媒体注册表、标题、日期三重校验；
  • 正文仍要过注册表 / 标题 / 日期 / 正文长度校验；
  • 存档回放仍只认 Wayback / archive.today 的可复核快照——云端渲染的 DOM 不是存档证据；
  • 媒体出口数、独立出处、反转载的近重复判定全部照旧；
  • 候选会标记为「经云端取回」，账目上能与直连区分。

同批还做了两项收紧：图集/视频页按首段路径拒绝（扫描 361 条唯一候选链接，命中 11 条，零误伤）；今日头条从媒体注册表迁入独立「聚合层」——可被识别、但不参与任何媒体侧统计，也不能成为取证目标。后者直接让 2026-01-201 退回合规单媒体，成为这批回补里第一条真正过完整门禁的事件。

08怎么核验

  • 出口对照可用任意公开 URL 复现：同一页分别以本机直连与云端渲染各取一次，比对结果块数量与落地地址。
  • 云端调用可在 Lexmount 控制台按 request_id / dom_id 回查，对应每一次结果页渲染与正文回退。
  • 命令：backfill:workflow --month 2026-01 --transport lexmount --stage supplement --resume；transport 不进配置哈希，可对已跑完的月份增量续跑。
  • 门禁结论以线上证据包为准：readyForReview、archive_status、replayVerified 全部由服务器侧判定，不由本材料声明。

本摘要基于 2026-11-01 的实跑记录，数字均为该次运行实测值。文中不含任何凭据、内部路径与未发布草稿内容；运行日志与原始任务包可按评审需要提供脱敏导出。
